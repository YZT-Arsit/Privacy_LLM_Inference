\section{Correctness Analysis}
\label{sec:correctness}

We use row-vector derivatives.  Correctness compares the canonical plaintext
model with masked execution under the same inputs, parameters, and trusted
operator results.  The following statements are identities over exact
arithmetic; they assume that masks have the dimensions in
Appendix~\ref{app:operators}, every inverse exists, and trusted operators occur
at the boundaries specified in Section~\ref{sec:method}.  They do not require
the transformed operands to be statistically independent of their plaintexts.

\begin{theorem}[Masked linear execution]\label{thm:linear-execution}
For any compatible $\X,\W,\bias,\Tpad$ and invertible $\Nin,\Nout$, the
construction in Eq.~\eqref{eq:method-linear} recovers exactly
$\X\W+\bias$ for any batch or sequence length.  The claim composes across
adjacent delegated linear maps whenever the output basis of one map is the
input basis of the next; otherwise the TEE recovers and remasks at the boundary.
Thus a private learned bias needs no public-coordinate copy.
\end{theorem}

The cancellation has two independent roles: $\Nin^{-1}$ removes the input
basis and $\Nout$ establishes the recoverable output basis, while
$\Tpad\W\Nout$ restores the part removed by the additive input pad.  Omitting
any required compensation term, or allowing an uncompensated pad to cross a
nonlinearity, is outside the theorem.

\begin{theorem}[Attention and cache]\label{thm:attention-cache}
Suppose RoPE is applied before masking, no mask mixes heads, and each query/key
pair satisfies $\NQ\NK^{\mathsf T}=\mathbf I$.  Then masked attention has the
same score matrix, softmax probabilities, and recovered output as plaintext
attention.  This remains true for GQA (and MQA) when all query heads sharing a
KV head use its tied key mask.  If $\NK,\NV$ remain fixed within a session,
appending masked KV rows is equivalent to masking the appended plaintext cache.
\end{theorem}

The compatibility condition cancels between each query and its addressed key
before scaling, causal masking, and softmax, so those operators receive the
plaintext score matrix.  Value aggregation preserves the right $\NV$ basis,
which the output projection removes.  Post-RoPE masking is essential here: a
pre-RoPE variant would additionally need its masks to commute with every
position-dependent rotation.  Changing a KV mask mid-session would likewise
make old and new cache rows incompatible.

\begin{theorem}[LoRA adaptation]\label{thm:lora-equivalence}
Let $\Apad\Bpad=\Amat\Bmat$ and let $\Nin,\Nout,\Umix$ be invertible.  The
forward construction in Eq.~\eqref{eq:method-lora-forward} recovers the
plaintext base-plus-LoRA linear map.  Given the correspondingly transformed
upstream gradient, Eqs.~\eqref{eq:app-lora-backward}--\eqref{eq:app-lora-gradient-pad}
recover the plaintext factor and input gradients.  Applying the same trusted
optimizer to these gradients therefore produces the same parameter update.
\end{theorem}

Rank-space mixing cancels because $\Umix\Umix^{-1}=\mathbf I$, and exact rank
padding changes neither $\Amat\Bmat$ nor its real-rank gradients after the TEE
adds the pad-gradient terms.  Gradient transformation is the adjoint of output
recovery, so the delegated backward products reduce to the plaintext chain
rule.  Update equivalence assumes identical initial adapter and optimizer state;
the optimizer itself remains trusted.  The theorem covers delegated linear
boundaries, not a GPU implementation of nonlinear backward operators.

Appendix~\ref{app:proofs} gives complete derivations and failure conditions.
Finite-precision executions are not bit-exact claims: synthetic CPU tests give
maximum absolute errors of $1.07\times10^{-14}$ (linear),
$4.26\times10^{-14}$ (attention), $8.88\times10^{-16}$ (cached decode), and
$1.62\times10^{-14}$/$9.99\times10^{-16}$ (LoRA forward/backward) in fp64;
the measured fp32 maxima are $6.68\times10^{-6}$ for linear execution and
$4.32\times10^{-6}$ for KV caching.  A real Qwen-0.5B CPU fp32 check gives
$1.79\times10^{-7}$ recovered-logit error and identical greedy tokens.  These
measurements validate numerical closeness only for the tested settings.  They
do not imply bitwise equality, bf16/GPU error bounds, correctness for untested
architectures, or token equality under sampling, top-$k$/top-$p$, or beam
decoding.
